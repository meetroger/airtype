# Dictation improvements

These controls are in Settings → AI. Existing settings and vocabulary are preserved.

**Escape:** while the floating window is visible, Esc cancels recording or processing and closes the window. In review (including an Insert in progress), it saves the edited draft in History, cancels any pending insertion, and closes. It also dismisses idle, result, notice and error panels. Escape is registered globally only for the floating window's visible lifetime, so it works while another application's editor retains focus and is released when the window closes.

- **Local Correction Pairs:** enter `misheard => correct`, one pair per line. Matching is exact and case sensitive; Latin identifiers require word boundaries. Longest match wins, and replacements never chain. Each side is limited to 80 characters. This stage works without AI or a network connection. Canonical vocabulary remains an AI hint; at most eight terms matched by spelling or normalized transliteration are recalled.
- **Review before inserting:** edit the final transcript in the expanded floating panel. The preview takes keyboard focus when it appears. **Enter** (Return or keypad Enter), Insert, or **⌘↩** activates the captured application, raises the original window, focuses the original field, and restores the captured selection when supported. Shift+Enter adds a newline. While an input method has marked text, Enter confirms that composition; press Enter again to insert. It verifies the destination again immediately before pasting. A failure keeps the editable preview, original target, and retry/Copy & close actions visible. Copy & close leaves the edited text on the clipboard and also saves it in History. Save only retains it in History. Repeated failures update one history entry instead of creating duplicates. To manually learn a correction in the preview, enter the original word and its edited replacement, then click Remember correction. Undo learning restores the preceding manual rules if they have not since been edited.
- **Automatic learning after insertion:** enabled by default. Correct a word in the original native editor after insertion; Airtype learns small word replacements when editing settles or focus leaves the field. A nonactivating notice offers Undo; the menu and Settings retain Undo after the notice expires. Automatic mappings are stored separately from manual rules. See [automatic edit learning](AUTOMATIC_EDIT_LEARNING.md) for behavior, limits and native integration checks.
- **History insertion:** focus the desired editor, open Recent Transcriptions from the menu bar, and click Insert on an entry. The history window shows the destination app and returns to that captured editor before pasting. Without an accessible destination, Copy remains available. Focus identities are kept only in memory while the picker/review is open, never persisted in History.
- **Spelled English words:** shared AI rules join individually spoken letters when they spell one intended name or identifier (`A R I O N 项目` → `ARION 项目`, `L L A M A` → `LLAMA`). A recalled preferred term supplies its canonical casing. Lists, quoted spaced spelling, variables, and ordinary single-letter words stay separate. These rules apply to enhancement, vocabulary alignment and translation even with a custom cleanup prompt. With AI enhancement off and no relevant vocabulary alignment, no model runs and unknown spelled words remain unchanged. This is model-based normalization, not a guarantee for arbitrary speech.
- **Output style:** Automatic chooses a scene from the original app and field. A manual style takes precedence over per-app rules, which take precedence over automatic detection. Example override: `com.apple.mail => Email`. Valid values are Chat, Email, Search, and Coding / Prompt. Styles affect AI enhancement; translation keeps its separate translation policy.
- **Local live drafts:** off by default. With MLX Local selected, a serial task decodes a snapshot of the latest 20 seconds every four seconds after the preceding decode completes. These are recent-speech previews, not a complete live transcript. Temporary snapshots are removed after decoding. Stop/cancel invalidates pending preview updates. Final transcription always uses the full recording. An in-flight native decode can still delay the final decode until it returns.
- **Nearby cursor context:** off by default, with a separate default-off switch for cloud sharing. Accessibility requests a range of at most 400 UTF-16 units around the original cursor; it never requests the whole field or a screenshot. Unsupported/secure fields and known password managers yield no context. Context is session-only, excluded from history and logs, and included as a separate untrusted JSON field for spelling disambiguation. Missing context never blocks dictation. No accuracy gain is assumed for a particular model.

Automatic delivery is bound to the captured app, field, and available selection. A changed target opens recovery review and saves the result in History instead of redirecting it. Only an explicit Insert restores focus. Closed windows, stale elements, unsupported focus/selection restoration, or a changed character count when restoring a moved selection stop delivery; same-length external edits cannot be reliably detected. History says “Paste sent” because posting Cmd+V does not prove that the editor accepted the text; delivery is never automatically retried. Cancellation after posting is treated as a sent paste, so it cannot offer a retry of an already posted operation.

## Validation

Run `scripts/check-personalization.sh` for correction boundary, non-chaining, recall (including spaced spelling), scene precedence, context sanitation, history retry deduplication and persistence checks. Run `sh scripts/check-review-keyboard.sh` in a desktop session to check native Return/keypad Enter dispatch, Shift+Return, input-method composition, and Return outside review. Build the Airtype scheme in Xcode (the Metal compiler component is required by MLX).

Desktop acceptance checks still require microphone and Accessibility permissions:

1. Dictate into TextEdit; switch to another app before completion. Confirm no automatic paste there and that the editable recovery preview appears. Click Insert; verify it returns to the captured TextEdit window and field. Close the target window and retry: the edited text and Copy & close must remain available, with one failed History entry.
2. Change the selected range during processing; confirm automatic delivery is refused. Start from a password field; confirm recording is refused.
3. Enable review, edit a word, remember it, and undo. Confirm the next dictation uses only the retained rule. Test Enter immediately after the preview appears, Enter while editing, Shift+Enter for a newline, Enter to confirm a Chinese input-method candidate, keypad Enter, Insert, ⌘↩, Save only, and Copy & close separately. Move focus to another field/window/app during preview, then verify Insert restores the original selection. Focus a different editor and open History from the menu bar; its Insert should paste the chosen entry there without manual copying.
4. Enable local drafts and speak for over 20 seconds. Confirm only recent speech appears during recording and the final output includes the full recording. Cancel during a draft decode and start another recording; confirm no stale update appears.
5. Use a loopback AI endpoint with context on; inspect its request for the bounded referenceContext field. With a cloud endpoint and cloud sharing off, confirm that field is absent. Repeat after cancelling and on a short recording.
6. Press Esc during tap-to-toggle recording, held recording, processing, editable review, and an error/result panel. Verify the window closes immediately; cancelled recording must not later insert on key release. Review edits should have one History entry. Start another recording immediately after dismissal; the old delayed hide must not close its new window. With no floating window, Esc should behave normally in the target application.

Design references: Arion's input ownership, edit-learning, and contextual rewriting decisions, reviewed from its public repository. This implementation retains Airtype's SwiftUI/MLX architecture.

Interaction source review: [macOS dictation delivery](https://github.com/AstraFoundry/Arion/blob/main/apps/desktop/infrastructure/macos/macos.go) follows the live external cursor at commit time and copies on unavailable delivery. [Clipboard picker delivery](https://github.com/AstraFoundry/Arion/blob/main/apps/desktop/bootstrap/clipboard_delivery.go) captures a destination before the picker opens, activates it, waits for readiness, checks ownership and pastes. Airtype uses the latter interaction for History; preview Insert deliberately restores the original captured editor.
